# Архітектура бекенда (чернетка для погодження, 15.11.2026)

## Прийняті рішення

| Питання | Рішення |
| --- | --- |
| Хто бачить живі ціни | Усі відвідувачі публічного сайту |
| Де працює бекенд | Спершу на цьому ПК, потім на сервері; код той самий |
| Що робить Java | Усе: живі потоки, щоденний збір даних, метрики, API, публікація сайту. Python-пайплайн переписується й прибирається |
| Стек | Java 21 + Spring Boot 3, збірка Maven |
| База | PostgreSQL + TimescaleDB (на диску E:) |
| Акції та ETF | Раз на день за цінами закриття, з позначкою «ціни закриття». Наживо лише крипта, валюти й золото. Ліцензований фід для акцій пізніше |
| Домен | Поки немає |

## Схема

```
Публічні веб-сокети                Java-бекенд на ПК (Spring Boot)              Cloudflare
───────────────────                ───────────────────────────────              ──────────
Binance  (крипта, 24 пари)  ─┐     ingest: WS-клієнти, перепідключення
Kraken v2 (валюти, золото)  ─┼──►  normalizer → Tick(asset, price, t_exch, t_recv)
mempool.space (блоки BTC)   ─┤     aggregator: остання ціна + свічки 1 хв ──► TimescaleDB
Solana RPC (слоти)          ─┤     latency: затримка мережі до біржі, час блоків
Ethereum publicnode (блоки) ─┘                     │
                                                   ├─► relay-push кожні 2 с ──► Worker + Durable Object ──WS──► браузери
Щоденні джерела (09:00)                            │                            (investment-hub.ceuvdo.workers.dev)
Yahoo EOD, BIS/FRED, World Bank,  ─► daily jobs ───┤
DefiLlama, research/*.json             метрики     └─► export catalog/series + deploy ──► статичний сайт
```

Сайт лишається статичним на Cloudflare. Живі ціни приходять через ретранслятор (Worker), а не напряму з ПК. Тому:

- **Домен і відкритий порт не потрібні.** ПК сам надсилає дані на Cloudflare, ззовні до нього ніхто не підключається.
- **Якщо ПК вимкнений,** сайт працює зі щоденним знімком і показує «живі дані недоступні, ціни на <дата>».
- **Переїзд на сервер:** той самий jar і та сама база, змінюється лише місце запуску.

## Модулі Spring Boot

1. **ingest.** Клієнт на кожну біржу (`java.net.http.WebSocket`). Перепідключення з паузою від 1 до 60 с, перевірка зв'язку (heartbeat), лічильник помилок.
2. **aggregator.** Остання ціна в пам'яті. Свічки OHLCV за 1 хвилину пакетно записуються в базу раз на хвилину. Окремі тики не зберігаються: це гігабайти без користі.
3. **latency.** Вимірює затримку до біржі, тобто різницю між часом події на біржі й часом отримання. Медіана і p95 за 5 хвилин. Ще рахує інтервали блоків BTC, ETH і SOL за останні 10 блоків.
4. **daily.** О 09:00 перенесені на Java завдання Python-пайплайна: історія з Yahoo (ціни закриття), BIS/FRED, World Bank, DefiLlama, імпорт `research/*.json`. Після цього перерахунок метрик: доходність за 1, 5 і 10 років, коливання, просадка, кореляція. Тепер їх рахує SQL у Timescale.
5. **api.** REST: `/api/catalog`, `/api/assets/{id}`, `/api/series/{id}?range=`, `/api/status`. Живий потік: WebSocket `/live` для локальних клієнтів.
6. **publish.** Щодня експортує знімок і деплоїть статичний сайт, як зараз. Кожні 2 с надсилає зміни цін у Worker. Запит підписаний секретом, тож чужі дані туди не потраплять.

## «Час продажу» тепер складається з двох вимірюваних частин

| Що | Виконання ордера | Гроші чи актив у вас |
| --- | --- | --- |
| Крипта на біржі | виміряна затримка мережі до Binance, наприклад 0,18 с | підтвердження мережі: BTC ≈ середній інтервал останніх блоків (наживо), ETH ≈ 12,8 хв до фіналізації, SOL ≈ 13 с |
| Акції та ETF США | < 1 с у години торгів (9:30–16:00, Нью-Йорк) | T+1, тобто 1 робочий день (правило SEC з 28.05.2024) |
| Біржі ЄС і Британії | < 1 с у години торгів | T+2 (перехід на T+1 з 11.10.2027) |
| Валюти (spot) | < 1 с, 24/5 | T+2 (USD/CAD — T+1) |
| Житло США | медіана днів продажу (Realtor.com через FRED, щомісяця) | плюс угода й реєстрація |
| Інші | з досліджень і звітів, з джерелом; якщо даних немає, так і пишемо | |

## База (TimescaleDB)

- **Довідники:** `groups`, `ways`, `assets`.
- **Метрики:** `metrics (subject, key, value, text, source, url, asof, trust)`.
- **Свічки:** `candles_1m` (hypertable). Стиснення після 7 днів. Безперервні агрегати для годинних і денних свічок.
- **Денна історія:** `daily_prices`, з джерел (Yahoo, BIS) за 10+ років.
- **Обсяг:** приблизно 50 живих символів × 1 440 хв ≈ 72 тис. рядків на день, тобто близько 26 млн на рік. Після стиснення виходить менше 1 ГБ на рік.

## Що встановлюється (усе на E:, бо C: заповнений)

- **JDK 21:** уже є, `E:\tools\jdk`.
- **Maven:** `E:\tools\maven`.
- **PostgreSQL 17 + TimescaleDB:** портативна збірка в `E:\tools\pgsql`, дані в `E:\data\pg`. Запускається як служба Windows.
- **Бекенд:** служба Windows, яка стартує сама при ввімкненні ПК. Логи в `E:\tools\logs`.

## Ризики

- **ПК як сервер.** Живі ціни є лише тоді, коли ПК увімкнений і не спить.
- **Ліміти Cloudflare на безкоштовному плані.** Worker витримує 100 тис. запитів на день, Durable Objects теж мають ліміти. Для бета-версії цього досить, при зростанні аудиторії треба буде переходити на тариф $5 на місяць.
- **Умови використання.** Binance і Kraken дозволяють публічно показувати ринкові дані з посиланням на джерело. Ціни закриття з Yahoo — ризик, доки немає ліцензованого фіду.
